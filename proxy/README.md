# Option B — M365 Agents Toolkit Custom Engine Agent proxy

This is the **Option B** integration path: a Custom Engine Agent (CEA) that fronts the
Foundry hosted agent, performs **Teams SSO → On-Behalf-Of (OBO)**, and calls the Capital
Markets backend so Azure AI Search is trimmed **per Teams user**.

> The full bot/app registrations and Azure infra are generated by the M365 Agents Toolkit
> (`atk`). The files here show the wiring (SSO/OBO config + message handler). Regenerate the
> scaffold with `atk new -c weather-agent -l typescript -n capmarkets-proxy` if you want the
> toolkit's complete `infra/` + `m365agents.yml`.

## Key wiring

- `env/.env.local.example` — `AzureBotOAuthConnectionName` (Teams SSO), `OBOConnectionName` /
  `OBOScopes=https://search.azure.com/.default` (downstream OBO), `BACKEND_URL`.
- `src/agent.ts` — on each message: Teams SSO → `exchangeToken` (MSAL OBO) → POST the backend
  `/api/demo/optionB/invoke`, passing the user's search token in
  `x-ms-query-source-authorization`.
- `appPackage/manifest.json` — Teams app manifest with `webApplicationInfo` for SSO.

## Run locally (no dev tenant)

```powershell
npm install
# Test in the M365 Agents Playground (no tenant/tunnel needed):
npm run test-tool
```

## Provision + publish to Teams

```powershell
atk provision --env dev
atk deploy --env dev
atk publish --env dev   # not supported in M365 Government (GCC)
```

Tenant-scope org sharing requires **M365 admin approval**.
